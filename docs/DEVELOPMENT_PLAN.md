# План разработки и изучения Java

Основа: [спецификация редакции 3](SPECIFICATION.md). Статус на 29.10.2026: документация, без реализованного приложения. Этапы не являются списком уже выполненных работ.

## Как работаем

Небольшая законченная часть → объяснение классов и движения данных → запуск → содержательная проверка → коммит. Перед следующим этапом владелец должен понимать текущую часть. Полный код системы за один шаг не генерируем.

## Конкретные примеры ООП

- Инкапсуляция: `Booking.confirm()` проверяет допустимость перехода; внешнему коду нельзя вызвать `setStatus(CONFIRMED)`.
- Композиция: заказ содержит пассажиров и строки стоимости; самолёт содержит места. Покупатель не наследуется от пассажира.
- Абстракция: `PaymentGateway` описывает контракт операции без зависимости сервиса от устройства симулятора.
- Полиморфизм: `BasicRefundPolicy` и `FlexRefundPolicy` реализуют `RefundPolicy`; вызывающий код использует общий контракт. Тестовый шлюз реализует тот же `PaymentGateway`, что и сохранённый симулятор.
- Наследование: естественно используется у собственных исключений от RuntimeException. Искусственная иерархия Customer extends Person и Admin extends Customer не нужна; роль пользователя — enum.
- Generics: `List<BookingPassenger>`, `Map<UUID, FlightSeat>`, типизированные репозитории и результаты. Отдельную декоративную generic-иерархию не создаём.
- equals/hashCode: обсудить отдельно для value object Money и JPA entities; не включать изменяемые статусы/ленивые коллекции в сравнение сущности.
- Исключения: бизнес-ошибка отличается от отказа БД и неизвестного результата шлюза; HTTP-преобразование находится на границе приложения.
- Конкурентность: Java-потоки посылают одновременные запросы, но защита инвентаря находится в PostgreSQL. `synchronized` одного JVM не заменяет её.

## Будущий локальный запуск

План: Java 21 + Docker с Compose + Maven Wrapper из репозитория. Команда Compose запускает PostgreSQL, команда Maven запускает Java-приложение в local-профиле. README будет содержать точные проверенные команды, env.example без секретов, демонстрационный сценарий и способы остановки/очистки БД. Система рассчитана на восстановление из исходников, миграций и демоданных; облачные процессы для локального запуска не нужны.

Каждая облачная задача уже изолирована: используем существующий checkout; Git worktree создаём только по явной просьбе пользователя.
